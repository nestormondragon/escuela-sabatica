# SVG-DESIGN.md

How the narrative artwork in this app is built, and how to build the next one.

The reference implementation is `src/components/CrackedVessel.jsx`, the clay
jar for Lección 4 (2 Corintios 4:7, *"tenemos este tesoro en vasos de barro"*).

---

## Why this document exists

The first version of this vessel was written as markup and never looked at.
It compiled, it was valid SVG, and it read as a dark perfume bottle with a
rectangular stopper, ear-shaped handles, and a glowing rune floating on the
surface. No amount of code review would have caught that, because nothing was
wrong with the code.

**An SVG is not done when it compiles. It is done when it has been rendered,
screenshotted, and judged.** Use the motif lab (below) and the rubric in
`docs/svg-quality-rubric.md`.

---

## Semantic groups

The vessel is composed in this order, each group with a stable id:

| # | Group | Purpose |
|---|---|---|
| 1 | `g-shadow` | cast shadow ellipse; grounds the object |
| 2 | `g-handles` | drawn **before** the body so the body occludes their inner edge |
| 3 | `g-fire` | the light inside, clipped to the silhouette |
| 4 | `g-body` | ceramic, painted **through the crack mask** |
| 5 | `g-bloom` | tight spill past the ceramic edge |
| 6 | `g-fracture-shadows` | dark lip where each sherd lifts away |
| 7 | `g-rim` | neck, flared lip, dark interior, catch-light |

Occlusion is what creates depth: handles behind the body, fire behind the
ceramic, bloom in front of both.

## Colour

Fired terracotta, lit from the upper left, resolving into warm charcoal.
Deliberately *not* driven from the app's `--clay` token, because the vessel
must read as a physical material in both themes rather than as a UI accent.

| Role | Value |
|---|---|
| clay highlight | `#c07b52` |
| clay mid | `#9d5836` |
| clay shadow | `#6b3a24` |
| clay deep | `#3b2116` |
| handles / foot | `#8a4d31` → `#331c12` |
| fire core | `#fff6e4` → `#ffd398` → `#f98f4c` → `#b8431f` |
| coral bounce | `#ff9a5e` at ≤0.5 alpha |

The fire's hot centre sits at `cx 42% cy 44%` of its ellipse, placed
deliberately **behind the primary fracture's main run** so the light seen
through the opening is the bright part of the flame, not its dim edge.

## Mask strategy (the important part)

The crack is **not drawn**. The ceramic is painted through a mask:

```
<mask id="…-crack">
  <rect …  fill="black"/>   <!-- nothing shows by default -->
  <path d={BODY} fill="white"/>   <!-- ceramic shows -->
  <path d={NECK} fill="white"/>
  …fracture slivers fill="black"  <!-- punched back out -->
</mask>
```

The fire is painted *before* the ceramic and clipped to the body silhouette.
Because the mask removes ceramic along the fracture, the fire behind is the
only thing left to see there. That is why it reads as a genuine opening
rather than a bright line laid over the surface.

The bloom layer is intentionally kept **tight** (`stdDeviation="5"`, bounded
filter region) so light spills a few units past the edge instead of forming a
generic halo around the whole object.

---

## Crack construction

**A stroke cannot taper.** `stroke-width` is constant along a path, so a
uniform stroke is exactly what makes a crack look like a neon rune. Every
fracture here is a *filled sliver* generated by `sliver(points, widths)`:
it walks the centreline, takes the normal at each point from the neighbouring
segment direction, offsets both sides by half the local width, and closes the
loop back along the other side.

Fracture spec, all satisfied by `FRACTURES`:

- one primary, origin high on the left shoulder, **7 direction changes**
- **3 secondary branches** plus 3 hairlines
- widths taper `7.4 → 0.8` units (spec: 6–8 at origin, 0.75–2 at tips)
- uneven spacing and angles; no symmetry, no lightning-bolt, no closed glyph
- polygonal edges on purpose: ceramic breaks in straight runs
- each fracture carries an offset dark sliver beneath it, which is what gives
  the opening ceramic thickness

Hairlines never open wide enough to show fire; they read as damage only.

## Animation timing

| Moment | Duration | Notes |
|---|---|---|
| entrance | 560 ms | `vessel-settle`, opacity + 0.955→1 scale, no bounce |
| fracture open | 700 ms | mask sliver widths scale with stage |
| fire / light | 900 ms | opacity transition per stage |
| fire drift | 3.4 s loop | `vessel-breathe`, ±14% opacity, 3.5% scale |

The fire *drifts*; it does not flicker. A flickering vessel reads as an error
state, and this artwork sits on screen for minutes.

All ambient motion is CSS keyframes, so it starts on mount regardless of tab
visibility and never depends on a JS flag. The global
`prefers-reduced-motion` rule in `index.css` zeroes both `animation-duration`
and `transition-duration`, so the completed illustration simply appears.

## Responsive detail

`variant="auto"` switches to compact below **96 px**:

- clay grain filter dropped (turbulence is invisible and expensive when small)
- hairlines and outer branches dropped
- primary fracture opened 25% wider to hold the read

Verified at 160 / 96 / 64 px. At 64 px the three required things still read:
a clay vessel, a broken surface, warm light from inside.

---

## Instance safety

Several vessels can render on one page (kit, ceremony, keepsake card, lab).
Every gradient, mask, clipPath and filter id is namespaced with `useId()`.

This was a real bug: before the fix the lab rendered 5 vessels sharing 7
identical ids, and every instance silently resolved to whichever definition
appeared first in the document. Verified after the fix: 3 instances, 60 ids,
**0 duplicates**.

---

## Accessibility

`role="img"` with `aria-labelledby` pointing at a `<title>` and a `<desc>`,
both in Spanish, both namespaced per instance. The description names what a
sighted reader sees: a handmade clay jar with a deep crack showing the light
burning inside.

## The review loop

```
npm run dev
open http://localhost:5173/?lab=barro     # one motif, all 5 stages, large
open http://localhost:5173/?lab=all       # the whole family side by side
```

Controls in the lab:

- **ver silueta** — flattens to a single fill. Pass 1: if the outline could be
  three different objects, the silhouette is wrong. Reject on shield, bottle,
  perfume container, trophy, lantern, lidded urn, lab flask.
- **tamaños 160/96/64** — Pass 4: legibility at real sizes.
- **modo día / noche** — flips `:root[data-mode]`, because theme tokens live
  on the root and a wrapper div cannot restyle a subtree. (My first version of
  this lab wrapped a div and silently tested night twice.)

The lab imports the real production component, never a copy, and is excluded
from production builds via `import.meta.env.DEV`.

## Building the next narrative asset

1. Draw the silhouette first. Render it flat black. Iterate until it is
   unmistakable with no colour, gradient, or detail.
2. Then material: gradients that agree on one light direction, surface
   texture, structural truth (wall thickness, real joins, a foot).
3. Then features: damage, light, wear. Use fills for anything that tapers.
   Decide where the light physically comes from and make it come from there.
4. Screenshot at every stage and every size. Score against
   `docs/svg-quality-rubric.md`. No category below 4.
5. Namespace every id with `useId()` before shipping.
6. Verify no unused defs, no empty groups, no duplicate ids in the rendered
   DOM. (SVGO cannot run on inline JSX with dynamic values; check the rendered
   output instead.)
